# Acceptance Levels

## Purpose

Distinguish design, source, product, and release acceptance.

## Levels

| Level | Means | Evidence |
| --- | --- | --- |
| Design | Contract written | Doc review, markdown gates |
| Source | Code compiles and unit tests pass | Build and test output |
| Product | User journey works honestly | Journey tests, surface status |
| Release | CI and full gates pass | check-all plus project CI |

## Honesty

Do not claim a higher level without evidence for that level.

## Mapping

Tasks name the minimum level in Acceptance sections. Task 02 is design.
Task 05 is product for one journey. Task 06 approaches release for the kit.
